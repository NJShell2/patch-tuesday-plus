Patch now: the top 3

Critical

1. November Patch Tuesday: 1,095 fixes, an actively exploited Outlook zero-day, and a 10.0 Entra flaw

Microsoft fixed 1,095 vulnerabilities in the November Patch Tuesday release, covering Windows, Microsoft Office, SQL Server, and developer tools. The one zero-day is CVE-2026-124194, a Microsoft Outlook spoofing vulnerability that is being actively exploited. It is rated Moderate with a CVSS of 6.5, and the advice from Security Now is to patch it first. No vulnerabilities were publicly disclosed before the patches shipped.

About 64 of the fixes, roughly 6 percent, were rated critical. The biggest number in the release is a CVSS 10.0 elevation of privilege flaw in Entra Device Registration, where an authorization bypass through a user-controlled key lets an unauthorized attacker elevate privileges over a network. There is also an Active Directory Domain Services remote code execution flaw at 8.8, an Exchange Server remote code execution flaw at 8.8, a Windows NAT remote code execution flaw at 8.1, and a Windows Schannel remote code execution flaw at 8.1. Sorted by type, the release holds 297 remote code execution flaws and 536 elevation of privilege flaws. Chain one of each and you have more code as root.

Who is affected: every Windows shop, and especially anyone running Exchange, Active Directory, or Entra. Outlook users are directly in the line of the one actively exploited bug.

Action: Patch CVE-2026-124194 first, then the Entra Device Registration 10.0, then Active Directory and Exchange. Work the rest of the 1,095 fixes into this week's cycle; the volume is high because AI-assisted vulnerability screening is finding flaws faster, and that pace is not slowing down.
Critical

2. SignDrop: Nightmare Eclipse drops a new Windows zero-day on Patch Tuesday

Nightmare Eclipse, the researcher who deliberately drops zero-days on Patch Tuesdays, did it again. The new flaw, dubbed SignDrop, gives local users full System rights on some versions of Windows. It lives in the Common Log File System, or CLFS, and works by forcing a privileged process such as Windows Defender to open a crafted CLFS container. By manipulating Windows Object Manager symbolic links, an attacker with ordinary user rights can get Defender to create a file using its System privileges, then abuse that file creation to elevate to System. The researcher says the same trick can turn off any antivirus or endpoint protection, because from the kernel's point of view the file creation request comes from the product's own legitimate process.

Researcher Will Dormann reproduced the exploit and confirmed it works as described, but not on all versions of Windows 11. It appears to require Windows 11 26H2 that has existed for more than 90 days, with the CLFS authentication mode set to 0 or 1. You can check by running winver and looking at the registry value under HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\CLFS\Authentication\Mode. Microsoft said it is investigating the writeup, has no evidence the vulnerability is being exploited in the wild, and says Defender blocks potential exploitation attempts. That last claim is unconfirmed.

Who is affected: organizations running Windows 11 26H2, especially machines that have been on 26H2 for more than 90 days. Ironically, the flaw stems from a security measure Microsoft introduced in October 2025 to prevent attackers from exploiting other CLFS vulnerabilities.

Action: Check your 26H2 fleet for the CLFS authentication mode value and identify the machines that meet the vulnerable conditions. Watch for a Microsoft patch or CVE assignment for SignDrop and prioritize it when it lands. Do not assume Defender alone covers this; the exploit is designed to work through Defender itself.
Critical

3. Synology patches a critical NAS flaw that lets attackers in without logging in

Synology disclosed two serious vulnerabilities in DiskStation Manager, the Linux-based operating system used in its NAS products. The first, CVE-2026-76954, is a SQL injection bug in the DSM Auth API rated critical with a CVSS of 9.8. It lets remote attackers read or write arbitrary files, or carry out denial of service attacks. The second, CVE-2026-85101, is a flaw in the DSM rsync tool rated important at 8.6 that lets attackers bypass authentication entirely to read specific files, write arbitrary files, or launch limited denial of service attacks. Both can be exploited remotely, without logging in.

Synology shipped the fixed DSM versions in October 2026 and disclosed the flaws roughly a month later, a common practice that gives users time to patch before the details go public. Fixes are available for DSM 7.4, 7.3, 7.2.2, and 7.2.1. Users with automatic updates may already have the patch, but anyone on a manual update policy should check for new DSM releases now.

Who is affected: any organization running a Synology NAS, and especially any NAS reachable from the internet. This is the second week in a row a remote authentication service turned out to be bypassable from outside, and the lesson is the same: remote authentication should never be exposed to the public internet in the first place.

Action: Confirm every Synology NAS is on a fixed DSM release, 7.4, 7.3, 7.2.2, or 7.2.1 with the October patch. If any NAS is reachable from the internet, take it off the public internet now, whether or not it is patched. Audit your own internet-facing services for anything that was never meant to be public.

FBI: AI hacking tool Artex breached networks in under three hours

The FBI warned that hackers are using autonomous AI hacking tools to launch cyberattacks across the US and globally, in a flash advisory covering financial services, government, tech, defense, phone and internet companies, and law firms. The open source tool Artex, an AI penetration testing platform, can move from targeting a system to active compromise in under three hours. It scans a victim's network for weaknesses, then exploits simple security bugs such as weak protections and exposed or stolen passwords to gain a foothold, then spreads across the network for databases, mailboxes, and other sensitive information.

The FBI confirmed earlier findings from Microsoft that hackers used Artex to break into IT management giant ConnectWise and gain access to the Microsoft 365 cloud environments of at least 2,250 of its customers, though ConnectWise told TechCrunch it does not have the visibility to confirm that number, so treat the count as unconfirmed. Artex was also used against South Korean financial institutions, where weak defenses and missing multi-factor authentication let attackers steal the personal data of at least 68,000 people. Security company Barracuda disclosed it was breached in an Artex-linked attack in which the tool found an exposed credential belonging to a third-party service Barracuda had not revoked; Barracuda could not rule out access from its logs, assumed the worst, and changed all of its customer credentials. Artex has since gone closed-source, but the FBI says the previous open source version continues to circulate and remains widely accessible.

Action: Assume attackers can move faster than your response time and harden the basics they exploit: multi-factor authentication everywhere, no exposed or stale credentials, and no penetration testing tools reachable from the internet. Review third-party service credentials and revoke any that belong to ended vendor relationships. The tools are noisy, so make sure your alerts actually fire on that noise.

Infoblox confirms a breach through a third-party vendor

Cybersecurity and automation giant Infoblox confirmed a security incident in which hackers accessed company information through one of its technology vendors. The vendor provides SharePoint data migration services, according to a notification Infoblox sent about the breach and two people with knowledge of the incident. One of those people said sensitive customer data was taken, which Infoblox has not confirmed, so treat that as unconfirmed. Infoblox has not named the vendor, but one person with knowledge said Infoblox has terminated its work with the vendor.

Infoblox said it has no indication that any of its products, cloud services, software updates, or build-and-release processes were involved. The company would not say how many customers were affected, or whether it had been contacted by the hackers or received any demands. It is working with outside investigators to understand the scope.

Action: If you use Infoblox, watch for official communications and review security logs related to interactions with Infoblox systems for suspicious activity. More broadly, this is a vendor-breach pattern: your data can be exposed through a supplier you never vetted. Check which of your vendors hold your data and whether their access is still necessary.

Uber: close to 150,000 drivers had license data stolen in the Fireworks AI breach

Uber is notifying close to 150,000 drivers that their personal and driver's license information was stolen during an October data breach at one of its tech providers. In notices filed with several US attorneys general, Uber said it was notified on October 9 that hackers broke in and stole internal credentials, which were used to access Uber's data. The stolen data includes drivers' names, addresses, dates of birth, and driver's license numbers. In a notice filed with Oregon's attorney general, Uber said it notified 149,346 people in total.

The provider is Fireworks AI, which lets developers access and use open-weight AI models. Fireworks reported a breach last month in which hackers stole customer information including billing data and some private AI datasets. Online productivity startup Notion and AI coding startup Cursor have both confirmed they had data stolen in the Fireworks hack. Uber said it had alerts enabled to detect unauthorized access to its Fireworks environment, but because the hackers used Fireworks' own internal credentials, no alerts were triggered. Fireworks attributed its breach to a financially motivated cybercriminal group whose goal is to sell stolen tokens for accessing large language models. No group has taken credit for the data theft. This is Uber's second known data breach this year.

Action: If your organization uses Fireworks AI, review their security posture and any vendor communications, and rotate credentials and tokens tied to the service. If any of your staff drive for Uber, point them at Uber's guidance and remind them to watch for identity theft using their license data. The lesson for your own monitoring: alerts that trust the vendor's own credentials will not fire when those credentials are the attack.

The week's big outages were not attacks

Two major outages dominated the week, and neither was a cyberattack, as far as anyone in a position to know can tell. On Thursday, Microsoft suffered a 14-hour outage across many of its Microsoft 365 services, most notably Outlook, starting around 12:30 p.m. ET. Exchange Online was at the root of the problem, and the outage hit Outlook, Teams, SharePoint Online, Copilot, and Defender XDR. Microsoft's own updates during the outage were confused and contradictory, and broad recovery was not reported until about 2:11 a.m. Eastern on Friday. Microsoft has promised a full after-action report.

On Friday, the FAA ordered a nationwide ground stop for domestic flights. The cause was the nation's radar tracking network, more than 4,000 ground-based installations still linked by pre-internet analog copper leased lines with 19.2K baud modems. A single misbehaving router in southern Arkansas appears to have flooded that fragile network with replies it could not handle, effectively DDoSing itself. CBS later reported that an update pushed to the network run by L3Harris triggered a reboot and then a crash. Google, meanwhile, took to X to announce that Gmail was working just fine, after outage reports circulated on the same platform. The Director of National Intelligence said the US is not facing coordinated cyberattacks and attributed the wave of disruptions to businesses patching their systems at a much larger scale than before, with some systems not coming back as expected.

Action: None beyond your normal outage playbook, but note the pattern: patching at scale is itself causing outages, so test restores and rollbacks as part of your patch cycle, and keep a second channel for status when your primary cloud goes dark.

Proton's Lumo AI assistant arrives on desktop

Proton launched Lumo Desktop for Windows, macOS, and Linux, bringing its privacy-focused AI assistant to personal computers. The app lets the AI carry out local tasks involving connected apps, personal files, and automations, with connectors for file-system access, shell execution, browser content fetching, and third-party services including Confluence, Dropbox, and Jira, plus local and remote MCP servers. Proton says users can decide for each connector which actions Lumo can perform automatically, which require approval, and which are blocked entirely, and that conversations and information from connected apps and files are never used to serve personalized ads or train AI models.

The launch lands the same week Apple announced tightened security settings for apps that request Full Disk Access, which AI desktop apps do. An AI agent with file and shell access is a powerful tool and a new attack surface in one package.

Action: Before anyone on your team installs an AI desktop agent, decide your policy: which connectors are allowed, which actions need approval, and which are blocked. Lumo's per-connector controls are the model to demand from any AI agent tool, not the exception.
